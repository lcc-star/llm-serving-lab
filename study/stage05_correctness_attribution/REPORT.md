# 阶段五实验 5.1：真实提示词输出分歧定位

状态：完成输出差异清点与 8 次 GPU 固定轨迹诊断。**阶段五尚未全部完成**：EOS/取消/分块、Radix 与 overlap、长时间资源回收和 Nsight 时间线仍待执行。

## 本次回答了什么

固定阶段四已记录的批次后，Graph 模式能完整复现所选基线及等待策略的原始输出。两种调度轨迹在相同 token 前缀下产生不同 logits，进而改变 greedy argmax。证据已从“最终文本不同”推进到“首次分歧前缀相同、候选分数不同”。这并未定位最早产生差异的算子，也不能单凭数值差值排除 KV 寻址或状态错误。

## 差异清点

只比较固定预算 1024 的 wait_time 与 prefill_first，共 6 场景 × 3 档 × 5 次 × 24 请求 = 2160 对请求。682 对输出不同，首次分歧均发生在第一个生成 token 之后。与阶段四 7040 对统计范围不同，不能混用分母。请求对可能跨配置复用同一来源提示词，不代表独立用户样本。

| 场景 | 请求对 | 输出不同 | 首 token 分歧 |
|---|---:|---:|---:|
| decode_new | 360 | 157 | 0 |
| kv_tight | 360 | 58 | 0 |
| long_burst | 360 | 151 | 0 |
| long_only | 360 | 165 | 0 |
| mixed_steady | 360 | 147 | 0 |
| short_only | 360 | 4 | 0 |

## 实验方法

从文件名固定排序后的第一个存在差异的 mixed_steady/near 对选取样本（24 请求，seed 50200，重复轮次 0）。这是一组确定性案例选择，不是总体随机抽样。

回放真实输入，并固定每轮请求准入顺序、prefill/decode 阶段与预算；逐批检查 UID 顺序和处理 token 数。没有强制写回原始输出，自然 greedy 生成。基线 1190 批，wait_time 1189 批；Graph/eager 各两次，共 8 次。每轮检查完成数、输出长度、cache 完整性和 8 个槽位归还。

诊断绕过实时策略选择，避免 CPU logits 拷贝影响时间阈值和到达时机。本结果用于数值定位，不验证策略触发条件，不用于吞吐或时延测量。输入、输出、候选 token ID、完整 logits 仅在本地忽略目录。

配置：A800、Llama-3.1-8B-Instruct、naive cache、65536 token 页、关闭 overlap、最大 8 个请求、预算 1024。来源版本和诊断脚本哈希见 [provenance.json](evidence/provenance.json)。

## 源码解释与限制

[greedy 采样](../../python/minisgl/engine/sample.py) 使用 `torch.argmax`。Graph 使用 float32 logits 缓冲区，并将模型输出复制进去；eager 观测为 BF16。见 [GraphCaptureBuffer 与 replay](../../python/minisgl/engine/graph.py)。**float32 缓冲区不等于模型做了 FP32 计算**，转换不能恢复已经丢失的精度。

Graph 还会按捕获大小 padding，eager 不使用同一捕获路径。因此本次关闭 Graph 同时改变了执行路径与可能的批次形状，不是仅对捕获机制的单变量消融。Graph/eager 不一致不能直接归因于 CUDA Graph 自身错误。当前批次大小相同也不代表此前的批次历史相同。

本轮确认固定执行条件下重复一致，以及相同 token 前缀下的 logits/argmax 分歧。尚未证明差异来自 BF16 舍入、GEMM 形状、注意力归约还是 KV 状态；也未证明跨策略语义等价。后续应先选一个早期分歧点，在前缀一致的前提下捕获隐藏状态和 KV 映射，必要时用相同隐藏向量做更高精度 lm_head 对照，再扩展案例。

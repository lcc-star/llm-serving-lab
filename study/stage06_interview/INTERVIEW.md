# 面试讲解与追问

## 一分钟介绍

我基于 Mini-SGLang 做了一个推理调度优化项目。问题是长请求 prefill 连续执行时，会拉长已有请求的输出 token 间隔；但直接改成 decode 优先，又会让新请求等待更久。

我在保留原有 KV 准入和分块预算的基础上，增加了按请求记录等待时间的策略，两类请求超时后获得调度机会，并为同时触发和资源不足定义明确规则。评估使用 ShareGPT 的真实提示词和人工生成的到达序列，区分调参集与评估集。

在 A800 稳定混合负载的五轮确认中，短请求 P99 ITL 中位数降低 53.31%，吞吐基本持平；突发负载有退化，所以我不把它称为通用最优策略。随后通过 Nsight 观察到连续 prefill 阻塞链缩短，并在正确性测试中修复 overlap 终止处理和 Radix 页表两个问题。

## 高频追问

**为什么不直接 decode 优先？**

它能缩短运行中请求的间隔，但新请求准入和 TTFT 明显变差。稳定混合确认中其吞吐中位数约 143.44 token/s，基线约 404.86；有限回放吞吐也受准入、到达与排空影响，不能将比值直接当作 kernel 性能。

**等待时间从什么时候开始？**

prefill 加入 pending，decode 加入 running 时开始；实际选中的请求在批次选择时重置，其他请求保留年龄。它包含上次批次执行与结果处理时间，不是纯排队空闲时间。计划到达至引擎接收的滞后计入评估 TTFT，但不计入这段策略等待。

**两边都超时怎么办？**

比较 `wait - threshold`，选超过各自阈值更久的阶段，相同则 decode。固定时刻下等价于选更早到期的阶段；不比较等待时间与阈值的比例。没有超时则延续 prefill 优先。

**为什么说“可执行请求”？能保证每个请求公平吗？**

pending 非空不代表 KV 或槽位够用，优先阶段可能组不出 batch，需要回退。策略只决定阶段优先顺序，不改变 prefill 队列内顺序，也不能解决永远无法满足的资源需求。通过持续双类需求测试验证机会，不宣称形式化的单请求等待上界。

**50 ms 能保证 ITL 小于 50 ms 吗？**

不能。阈值只能触发下一次选择，已启动的 GPU 工作无法任意抢占；还有分块执行、资源准入及双方超时竞争。阶段等待和客户端 ITL 也不是同一指标。

**prefill 预算越小越好吗？**

较小分块减少单次占用，却增加批次数与调度/执行开销，可能降低吞吐。稳定混合 tune 的预算 256 虽然 P99 更低，却未满足基线 95% 吞吐门槛；所以选 1024。突发最终选 4096，说明最佳预算依赖负载。

**53.31% 怎么计算？**

用未舍入的两组五轮 P99 中位数计算 `1 - wait/base`。每轮 80 请求，40 个短请求各生成 256 token，对应 10200 个短请求相邻 token 间隔。同 batch 输出时间相关，不能当作独立同分布样本，五轮极差也不是置信区间。

**如何避免挑选最好结果？**

先固定预算比较三策略；只用 tune 集选择预算，再用不同 seed 的 eval 确认。发布全部场景和五轮范围，包括默认突发退化、KV 紧张分组退化及稳定混合慢轮次。仍只有有限样本，不能宣称统计显著的通用收益。

**Nsight 证明了什么？**

代表性输入下，两侧总工作量接近，但最长连续 prefill 阻塞链缩短，支持调度顺序改善机会。NVTX GPU 投影覆盖首尾操作，可能含空隙；默认 graph 追踪没有展开所有内部 kernel。每策略一次，只作机制证据，不重新估计 P99。

**改调度为什么会改变输出？是不是有 bug？**

先排查相同输入、首次分歧前缀、KV 映射、历史 KV 与隐藏状态，不能直接说浮点误差。一个案例 Q/K/V 一致，最早观测差异在 attention backend，BF16 候选舍入打平导致 argmax 变化。但这只解释部分链条，具体内核原因和所有输出差异仍未穷尽；另外生命周期测试确实找到了两个独立缺陷。

**overlap 的 bug 怎么修？**

GPU 已经执行下一批时，主机可能才收到 EOS。终止后要丢弃后续结果，按实际主机输出长度判断结束；使用在途批次数延迟资源释放。取消还要查找已离开队列但仍在途的请求，复用前确保引擎 stream 排队写入完成。

**Radix 为什么需要复制被释放的页号？**

两个请求产生重复前缀后，活跃页表需要改指向共享规范页，再释放原重复页。如果延迟释放持有页表切片视图，改页表会把待释放页号也改掉，因此先 clone 原页号。例如 `[4,5,6,7]` 改为 `[4,5,8,7]`，应释放 `6`，不能释放 `8`。

**测试通过是否代表输出语义正确、不会泄漏？**

生命周期测试真实执行模型，但强制采样以稳定触发边界，只验证控制流与资源状态。十分钟资源检查通过是有限证据。固定轨迹自然生成回放另行检验输出重复性；仍没有完整语义质量评测。

**为什么暂不支持 TP？下一步如何扩展？**

各 rank 本地时钟可能做出不同决策。可由统一调度 rank 决策并广播批次；这是待实现方案。另一方向是按测得的批次时间调整 prefill 预算，但应先定义吞吐与尾延迟约束，避免加入难以解释的自适应规则。

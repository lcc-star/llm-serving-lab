# 调度优化实验计划

目标：改善长短请求混合负载的 decode 尾延迟，同时报告 TTFT 和吞吐量代价。

1. 建立请求与调度轮次记录，区分引擎 token 时间和客户端文本块时间。
2. 使用短输入 128 / 输出 256、长输入 4096 / 输出 128 的可控负载复现 prefill 干扰。
3. 对照原始 prefill 优先、decode 优先及带等待时间约束的分阶段调度。
4. 覆盖稳定流量、突发流量、纯短/纯长请求和 KV 容量压力。
5. 验证 EOS、长度上限、取消、分块、缓存回收与重叠调度正确性。
6. 单独采集 Nsight Systems 时间线，解释收益与适用边界。

数据：先用固定种子的合成 token 与到达序列；后用 Qwen-Bailian Trace A/B 的长度和到达轨迹验证，WildChat 补充真实文本。匿名 block hash 不是 token ID。记录超长请求处理规则，分离调参和评估数据。

性能实验按同一到达序列比较，预热后独立重复测量，报告 P50/P95/P99 TTFT、ITL、端到端延迟、吞吐量及错误率。P99 需要足够样本；不以已有 Graph/TP 开关收益冒充新增优化。
